Interview App · Documentation

API contract#

Base URL: http://127.0.0.1:8765 (local only). JSON in and out. Errors use FastAPI's shape: {"detail": "message"} with a 4xx/5xx status. Timestamps are ISO-8601 UTC strings.

Every agent-produced object carries a meta block describing how it was made:

{"trace_id": "trc_…", "provider": "ollama | claude | heuristic", "model": "qwen3:14b",
 "status": "ok | repaired | fallback | degraded", "attempts": 1, "latency_ms": 2140}

degraded means no language model was available and built-in rules produced the result.

Targets (a job you're preparing for)#

  • POST /api/targets {"title"?, "company"?, "resume_text", "jd_text"} → 201 {"target": Target, "job_id"} (starts the prep pipeline in the background)
  • GET /api/targets → [{"id", "title", "company", "status", "created_at", "match_score", "question_count", "story_count", "session_count"}]
  • GET /api/targets/{id} → Target
  • DELETE /api/targets/{id} → {"ok": true}
  • POST /api/targets/{id}/prepare → {"job_id"} (re-run the full prep pipeline)
Target = {id, title, company, status: "new|preparing|ready|failed", job_id, resume_text, jd_text,
          profile: CandidateProfile|null, job: JobAnalysis|null, fit: FitAnalysis|null,
          meta: {profile?: Meta, job?: Meta, fit?: Meta, stories?: Meta, questions?: Meta},
          created_at, updated_at}
CandidateProfile = {name, headline, years_experience, skills: [str],
                    roles: [{title, company, period, highlights: [str]}],
                    projects: [str], education: [str], achievements: [str]}
JobAnalysis = {title, company, seniority, must_have_skills: [str], nice_to_have_skills: [str],
               responsibilities: [str], competencies: [{name, weight: 1-5, why}],
               interview_focus: [str], keywords: [str]}
FitAnalysis = {match_score: 0-100, summary, strengths: [{skill, evidence}],
               gaps: [{skill, mitigation}], talking_points: [str]}

Practice sessions#

  • POST /api/sessions {"target_id", "mode": "mixed|behavioral|technical", "num_questions": 3-12, "persona"?: "friendly|neutral|challenging", "answer_time_limit_sec"?, "hints"?: bool, "focus_competency"?} → 201 Session (includes the first turn)
  • GET /api/sessions?target_id= → [{"id", "target_id", "target_title", "status", "mode", "started_at", "ended_at", "overall_score", "answered"}]
  • GET /api/sessions/{id} → Session
  • POST /api/sessions/{id}/hints {"turn_id", "transcript", "elapsed_sec"} → {"hints": [Hint], "star": {"situation", "task", "action", "result"}, "metrics": AnswerMetrics} (practice only; call every ~4-5 s while answering)
  • POST /api/sessions/{id}/answer {"turn_id", "answer_text", "duration_sec", "self_rating"?: 1-5} → {"turn": Turn, "next_turn": Turn | null, "done": bool}
  • POST /api/sessions/{id}/skip {"turn_id"} → {"next_turn": Turn | null, "done": bool}
  • POST /api/sessions/{id}/end → {"job_id"} (builds the session report; status finishing → done)

AnswerMetrics = {word_count, duration_sec, wpm, filler_count, filler_rate, fillers: {word: count},

Evaluation = {overall: 1.0-5.0, scores: {structure, relevance, specificity, impact, communication,

Meeting notes#

  • POST /api/meetings {"title"?, "template"?, "consent_confirmed": true, "consent_note"?} → 201 Meeting (status live; 400 if consent isn't confirmed)
  • GET /api/meetings?q=&limit=50 → [{"id", "title", "template", "status", "started_at", "ended_at", "duration_sec", "segment_count", "snippet"}] — with q, full-text search; snippet marks matches with \u0002…\u0003 (escape the text first, then turn the markers into <mark>).
  • GET /api/meetings/{id} → Meeting
  • PUT /api/meetings/{id} {"title"?, "user_notes"?, "template"?, "notes"?: EnhancedNotes} → Meeting
  • DELETE /api/meetings/{id} → {"ok": true}
  • POST /api/meetings/{id}/segments {"speaker", "text", "t0", "t1"} → Segment (used when the browser does speech recognition)
  • POST /api/meetings/{id}/stop → {"job_id"} (ends the meeting, writes enhanced notes, indexes)
  • POST /api/meetings/{id}/enhance {"template"?} → {"job_id"} (re-run on a saved meeting)
  • GET /api/meetings/{id}/search?q=&scope=meeting|all → {"hits": [{"meeting_id", "meeting_title", "segment_id", "speaker", "t0", "text", "snippet"}], "took_ms"} — works live: finds where something was said.
  • POST /api/meetings/{id}/recap {"minutes": 5} (0 = whole meeting) → {"recap": [str], "decisions": [str], "open_questions": [str], "window": {"from_sec", "to_sec"}, "meta"} — works live; summarizes only what was said.
  • POST /api/meetings/{id}/ask {"question"} → {"answer", "citations": [{"segment_id", "speaker", "t0", "text"}], "not_found": bool, "meta"} — only after the meeting is saved (409 while live).
  • POST /api/ask {"question"} → same shape across all saved meetings; citations add meeting_id, meeting_title.
  • POST /api/meetings/{id}/redact {"minutes": 2} → {"deleted": 5} — privacy control, works live: deletes the last N minutes of transcript (and its search index entries).
  • GET /api/recipes → [{"id": "follow_up_email", "name": "Follow-up email", "description"}]
  • POST /api/meetings/{id}/recipe {"recipe": "follow_up_email | slack_summary | todo_list"} → {"recipe", "title", "body", "meta"} — saved meetings only (409 while live).
  • GET /api/meetings/{id}/export.md → Markdown file
  • POST /api/meetings/{id}/to-practice {"target_id"} → {"added": 3, "questions": [Question]} (interview-debrief notes: adds the questions you were asked to that target's practice bank)
Meeting = {id, title, template, status: "live|processing|ready|failed", consent_confirmed, consent_note,
           started_at, ended_at, duration_sec, user_notes, segments: [Segment],
           notes: EnhancedNotes|null, notes_md, job_id}
Segment = {id, speaker: "Me|Them|…", t0, t1, text}
EnhancedNotes = {title, summary, sections: [{heading, bullets: [{text, source: "you|ai", refs: [segment_id]}]}],
                 decisions: [str], action_items: [{task, owner, due}], open_questions: [str],
                 questions_asked: [str], meta}

Speech-to-text#

WS /api/stt/ws?mode=practice|meeting&meeting_id=&channel=me|them&offset=<seconds>#

  1. Server sends {"type": "ready", "engine", "model", "device"} — or {"type": "unavailable", "detail"} and closes (the client then falls back to the browser's speech recognition, mic only).
  2. Client streams binary frames: 16 kHz mono PCM16 little-endian, ~100-250 ms per frame.
  3. Server sends {"type": "partial", "channel", "text"} while you speak and {"type": "final", "channel", "text", "t0", "t1", "segment_id"} at each pause. In meeting mode, finals are saved as segments: channel me → speaker Me, them → Them.
  4. Client sends {"type": "stop"}; server flushes, sends remaining finals, then {"type": "done"} and closes.

POST /api/stt/transcribe (multipart file: webm/wav/ogg/mp3)#

→ {"text", "segments": [{"t0", "t1", "text"}], "duration_sec", "engine"}
